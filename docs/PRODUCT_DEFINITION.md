# ForgeCAD 产品定义与范围

版本：2026-07-29
状态：目标产品与范围权威；当前实现仍是本机 Alpha，已实现能力只以 `USER_GUIDE.md`、状态账本和当前 Gate 为准

## 1. 产品一句话

目标产品面向用户的名称是 **Forge Studio**：一款面向非专业创作者和小型内容团队的轻量、类别开放、高自由度、外观优先、可编辑通用 3D Agent。用户上传什么对象的授权图片并描述什么对象，千问形成视觉证据合同，DeepSeek 编写受限设计程序，系统按部件选择程序化、形变或本地混合表示并生成真实 GLB/PBR；固定多视图验收后最多执行一次 typed patch，用户确认后才创建可继续语言修改、恢复和导出的不可变资产版本。

仓库和内部兼容标识当前仍使用 ForgeCAD。当前实现是本机 Alpha，已经具备 Rust-owned 状态、DeepSeek 受限程序化机械臂/机械硬表面生成、千问只读视觉证据、真实 GLB/PBR/readback、唯一结果、确认/版本/导出/恢复等工程闭环。旧 U004 远程 Mesh Seed 实验候选已退役，没有成为 capability，也没有进入版本真值。角色、生物、植物和环境等本地正式表示路径仍未实现，也尚未通过跨类别未见任务与真人视觉门。不得把“类别入口开放”描述成任意图片已经能生成任意高质量 3D。

产品名称不再使用 “Weapon Concept Agent” 作为总产品名。武器只保留为第一批领域包之一：`future_weapon_prop`。

## 2. 类别开放与质量晋级

产品入口从第一天就按**类别开放**设计：物体、角色、人形、生物、植物、自然物、家具、建筑/环境道具、车辆、航空器、机械和混合设计都可以成为目标。系统不要求用户选择 Mode 或 Domain Pack，也不因未知类别把对象替换成机械臂或未来武器。

机械硬表面仍是当前最成熟、首个重点优化的表示路径，因为它最适合现有 typed source、PBR、readback、版本和局部修复底座；这是质量成熟度排序，不是产品类别封锁。其他类别按 `RepresentationPlan` 选择本地形变、程序化或混合表示，并在各自正式盲测通过前明确显示 `best effort`、需要补充视图或当前能力受限。

首批四个 Domain Pack 继续保留为兼容知识包和机械回归集，不再是入口 allowlist：

| 领域包 | 面向用户的说法 | 新产品角色 |
| --- | --- | --- |
| `robotic_arm_concept` | 机械臂与机器人机构 | 当前 procedural regression，不是默认回退 |
| `future_weapon_prop` | 未来武器概念道具 | 非功能虚构视觉知识与安全用途规则 |
| `vehicle_concept` | 汽车与地面载具 | 车辆视觉语义、部件和材质知识候选 |
| `aircraft_concept` | 飞机与航空器 | 航空外观语义、部件和材质知识候选 |

用户不进入四个 Mode，也不需要手动选择领域包。U002 Agent 已从图像与描述形成 `SubjectProfile`；只有对象身份、视图关系或关键意图确实含糊时才问普通语言问题。有限关键词、`unsupported` 和四领域选项只保留 legacy 兼容测试；当前没有可执行表示时明确返回 typed limitation，禁止回退成任何已有模板。

质量声明按表示能力和冻结跨类别基准晋级，不按“是否登记 Domain Pack”准入。新增知识包可以提高角色、部件、比例和材质理解，但不能决定对象是否允许生成。任何类别都不能据此获得制造、安全、医疗或认证结论。

当前实现排序采用**质量优先**：U004 先最大化对象身份、完整轮廓、中观结构、可见细节和 PBR 保真，不以减少一次图像理解、降低面数或缩短等待换取更差结果。时间、DeepSeek/千问用量和内存继续记录并设置失控上限，但在跨类别候选尚未达到独立真人视觉门之前，不把“更快”作为牺牲外观质量的优化目标；质量达标后再做缓存、LOD 和压缩优化。

### 2.1 核心用户与核心任务

核心用户：

- 需要快速制作硬表面道具、机器人或设备概念的游戏/影视/UGC 小团队；
- 会写提示词、会选择参考图，但不会完整 Blender/CAD 工作流的独立创作者；
- 需要多轮语言修改、可导出资产和版本恢复的早期工业外观团队；
- 需要本地项目数据、可审计 lineage，以及 DeepSeek/千问 BYOK 或企业部署的私有流程。

核心任务不是“生成一张好看的 3D 截图”，而是完成：

```text
描述/授权参考
→ 可解释的外观合同
→ 唯一真实 GLB/PBR
→ 多视图验收与有界修复
→ 用户确认
→ 继续修改同一资产
→ 标准导出与重启恢复
```

首个付费版本应优先证明该闭环被同一用户重复使用，而不是用一次性 showcase 或模型排行榜证明市场价值。

## 3. 零基础用户主流程

以下是 P0 目标流程。当前可验证的缩减流程以 [USER_GUIDE.md](USER_GUIDE.md) 为准。

```text
自然语言或本机只读授权参考
  → 千问形成 observed/inferred/unknown 视觉证据
  → Rust 封存 SubjectProfile / VisualFeatureContract / RepresentationPlan
  → DeepSeek 形成视觉 Brief 和 Detail Inventory
  → DeepSeek 通过 typed Product Tool 编写 ForgeVisualProgram
  → Rust 校验并降低到 ShapeProgram / AssemblyGraph / Surface Program
  → 受限编译器生成 PBR GLB
  → Rust 回读和固定八视角检查
  → 只展示一个未保存结果
  → 用户确认后创建不可变版本
  → 用自然语言修改或重新生成子版本
  → 导出 GLB / ForgeAssetPackage
```

首屏只保留：Agent 对话、单一 3D 主视图、步骤状态、撤销、检查和导出。Connector、Joint、ShapeProgram、拓扑、坐标和格式等专业信息按需展开。

### P0 产品验收故事

方案只有同时满足以下故事，才算真正覆盖“通用参考条件 3D Agent”，而不是把机械臂模板换名字：

1. 用户输入纯文字、文字+单图、文字+多视图或已有资产局部修改，Agent 保持输入对象身份，只展示一个通过真实编译/readback 的**完整外观**结果，或明确说明缺少视图、表示不可用、质量受限或 Provider 不可用；
2. 结果在宏观轮廓、中观结构、微观细节、PBR、跨视图一致性和资产可用性六层都有可检查证据，而不是单个局部、英雄角度或生产密度 blockout；用户不需要在三张方向卡中替 Agent 评审；
3. 模型能转为可编辑资产，至少包含领域角色明确的层级分件；
4. 选中任一可编辑部件后，可以用普通语言调整比例/位置/概念姿态或替换兼容部件；
5. 可以只给指定部件/材质区域应用视觉材质，其他部分保持不变；
6. 每次永久修改都先预览、再确认、再创建新版本；取消不产生永久副作用；
7. 检查、当前选择、版本和导出始终指向同一 `ActiveDesignSnapshot`；
8. 新用户不安装神经 3D、Blender、Unity、CUDA、模型权重或开发 Skill，也能完成首次 GLB 导出；
9. 未识别对象不按领域拒绝；真正含糊时进入一个简短澄清问题，并且绝不默认变成机械臂或武器；
10. 跨类别冻结未见任务、工作台 E2E、重启恢复、本机安装、时间/成本和独立真人门全部通过；每个类别单独报告，不能用机械硬表面平均分掩盖角色、生物或自然物失败。

当前实现只覆盖其中一部分，因此产品仍是 Alpha。退出条件和任务顺序见 [CODEX_EXECUTION_PLAN](CODEX_EXECUTION_PLAN.md) 与 [CODEX_TASK_INDEX](CODEX_TASK_INDEX.md)。

## 4. 编辑能力边界

目标状态下，每个已确认部件都应能单独：

- 让 Agent 调整外观或比例；
- 修改尺寸、位置、旋转和概念姿态；
- 替换为同角色、同领域且通过质量检查的组件；
- 只给该部件或材质区域换视觉材质；
- 隐藏、隔离、锁定、撤销和恢复；
- 保存为可复用组件。

所有永久修改都走 `ChangeSet preview → confirm → new AgentAssetVersion`，不会静默覆盖当前版本。

当前只实现固定比例/位置/部分关节姿态、13 个六类视觉材质、项目内组件保存和同角色替换，以及已确认 Agent 修改的服务端撤销/重做；隐藏、隔离、锁定、自由参数、任意版本历史浏览和深度分件尚未完成。

确认前后的检查会提示未声明装配关系的部件是否在概念包围盒中明显重叠。它是零基础用户的防呆提示，不是精确网格碰撞、间隙、公差或运动学结论。

用户也可以导入自包含 `.glb` 作为**参考模型**。导入时应用验证 glTF 2.0、内嵌缓冲、外部资源、三角预算、访问器范围和 SHA-256；参考模型可以在同一主视图中查看、检查和原样导出，但不会被伪装成可编辑 ShapeProgram。要继续逐部件编辑，用户应让 Agent 依据参考模型重建一个新的可编辑概念资产。

## 5. 轻量技术路线

默认不安装本地神经 3D 模型、CUDA、ComfyUI 或模型权重，也不购买第三方远程 Mesh 服务。运行时 AI Provider 固定为 DeepSeek 与千问：DeepSeek 通过 typed Product Tool 编写受限设计源，千问分析授权图片并比较候选视图；Rust 负责 Schema、预算、hash、降低、GLB/PBR 回读、版本、质量、导出和恢复；桌面端始终复用单一 Three.js renderer。Luna 只用于仓库开发，不是产品运行时依赖或资产真值。完整边界见 [ADR-0023](ADR/0023-deepseek-qwen-only-ai-provider-policy.md)。

`UniversalAssetSource@1` 统一承载 procedural、parametric/deformable、local hybrid 和 material/projection source；`ForgeVisualProgram@2` 是当前设计源，继续绑定现有 `ShapeProgram`、`AssemblyGraph`、Recipe、Material Zone 和 Surface Compiler。兼容 schema 中的 `mesh_seed` 保持 unavailable，不能触发远程生成。任何视觉理解或外观候选都不能绕过 GLB/readback、唯一结果、确认和版本链。通用产品与能力沙箱见 [ADR-0022](ADR/0022-universal-reference-conditioned-3d-agent.md)，Provider 边界见 ADR-0023，程序语言和 1+1 预算见 ADR-0021，小团队成本纪律见 ADR-0020。

### 5.1 小团队成本纪律

- 不训练基础 3D 模型，不自建常驻 GPU 集群；
- 本地范围、Schema、预算、缓存和 deterministic hard gate 优先于付费推理；
- 同一意图最多一次 typed patch，不允许无限 Agent loop 或整份创意重写；
- 默认 1K PBR，2K/4K 和高成本生产档按设备能力或进入高阶套餐；
- 每次真实 DeepSeek/千问实验记录调用、用量、耗时、缓存、修复次数和估算成本；
- 没有用户/操作者明确授权时，联网和计费调用为 0；
- 平价订阅不承诺无限高成本生成；DeepSeek/千问 BYOK 或企业部署必须遵守相同权限和 lineage。

商业验证目标是可变推理与存储成本不高于实收收入的 25%。该数字在真实付费试验前属于 `target`，不能写成当前单位经济已成立。

## 6. 明确不做的事情

以下是不提供的执行能力或现实用途，不是禁止生成这些对象的视觉外观：

- 未来武器外观仅限虚构游戏资产、影视道具和非功能展示；不提供现实武器制造图纸、制造尺寸、机构、弹药、工艺或性能建议；
- 汽车安全、动力、碰撞或道路认证；
- 飞机空气动力学、结构强度、适航或飞行控制；
- 机械臂载荷、扭矩、碰撞安全、控制代码或工业认证；
- B-Rep/STEP 工程 CAD、完整 DFM、切片和制造就绪结论；
- 在 Agent 中执行任意 Python、JavaScript、shell 或外部 URL；
- 将旧任务中心、Mode、Forge、独立资产库重新变成产品导航。
- 商城交易、游戏技能、战斗数值、多人游戏和第二款游戏软件；
- 第一阶段的手工拓扑、复杂参数编辑和神经 GLB 参数化承诺；
- 默认要求用户购买或配置远程图像/神经 3D 服务。
- 第一阶段训练自有基础模型、建设 GPU 集群或向所有用户分发大权重；
- 用 Luna 或任何开发模型的文字判断代替真实 Gate、真人评分和用户行为；

## 7. 商业验证与收窄条件

首批采用 5–10 家付费设计伙伴的封闭验证。目标门如下，当前均为 `target`：

- 冻结跨机械/产品、角色/人形、生物、植物/自然物、家具/生活物、建筑/环境、载具和混合对象的未见任务；
- 首次结果独立真人 `≥4/5` 比例至少 70%，一次 typed patch 后至少 85%；
- 无 patch P50 ≤32 秒/P90 ≤70 秒，一次 patch 后 P90 ≤105 秒；
- 严重视觉/版本回归率 `<10%`；
- 可变成本不高于实收收入的 25%；
- 至少 5 家付费伙伴，第 4 周仍每周使用创建→修改→导出核心闭环的不少于 50%。

若通用入口仍把对象映射到整机模板，先完成 U002/U003，不继续堆模板；若某类表示长期不达标，产品必须诚实显示该类 `best effort` 或能力受限，但不得重新引入类别 allowlist。若 1+1 时间/成本不达标，优化本地表示、缓存与 DeepSeek/千问上下文；若重复使用和付费不成立，再按真实用户数据收窄商业定位，同时保留通用资产真值与类别开放接口。

## 8. 文档使用规则

文档中出现的能力必须标明状态：

- **已实现**：有代码路径和 smoke/E2E 证据；
- **兼容基线**：旧 Weapon/Unity/Provider 路径，只用于回归；
- **目标设计**：合同或界面已定义，但没有实现证据；
- **发布阻断**：需要真实 Provider 评测、外部 GLB 的自动重建/深度分件、碰撞/运动学、正式资产审阅或打包 sidecar。
