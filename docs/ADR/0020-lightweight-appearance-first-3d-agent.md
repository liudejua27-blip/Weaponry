# ADR-0020：小团队轻量、外观优先的 3D Agent 收敛路线

日期：2026-07-28
状态：Accepted
决策范围：产品切入点、生成架构、质量合同、成本边界与商业验证；不代表相关能力已经实现

2026-07-29 取代说明：ADR-0022 已取代本文将机械硬表面作为产品类别范围或通用入口前置门的部分；本文的小团队成本、轻量安装、外观优先、单一真值和商业纪律继续有效。

## 1. 背景

ForgeCAD 已经证明了下列工程基础可以在本机 Alpha 中共同工作：

- Rust-owned Agent 与产品状态；
- 受限 typed design source、几何编译与真实 GLB/PBR readback；
- 单一结果、`preview → confirm → immutable version`；
- `ActiveDesignSnapshot`、内容寻址对象、导出与重启恢复；
- 授权图片、contact sheet 和 GLB 的只读证据链；
- 固定多视图与确定性硬门；本 ADR 记录的两次同一意图原位修复已由 ADR-0021/0022 的一次 typed patch 取代。

这些能力解决了“结果如何可信地进入项目并继续编辑”，但没有解决“每次都能生成用户肉眼认可的高质量外观”。项目长期无法完成的主要原因不是缺少更多 API、页面或导出格式，而是产品目标同时覆盖任意类别、照片级质量、工程可编辑、四领域、低成本、本地运行和生产发布，导致退出条件无界；同时，工程闭环曾多次被误当成视觉质量闭环。

公司规模和预算决定了 ForgeCAD 不能依靠训练基础 3D 模型、长期维护 GPU 集群、向用户分发大型本地权重或无上限调用昂贵 Provider 来获得竞争力。必须选择一个可以用现有资产生命周期、可编辑中间表示和局部修复形成差异化的位置。

## 2. 决策

ForgeCAD 第一阶段收敛为：

> 面向非专业创作者和小型内容团队的轻量、外观优先、可编辑硬表面 3D Agent。用户用提示词和明确授权的图片描述目标；Agent 将意图写成受限设计源，系统生成真实 GLB/PBR，以固定多视图和质量合同验收，最多进行两次有界局部修复，只展示一个结果；用户确认后才形成可继续编辑和导出的不可变资产版本。

“轻量”同时约束安装、运行、团队和单位经济：

- 用户默认不安装 CUDA、ComfyUI、Blender、神经 3D 权重或开发 Skill；
- 桌面客户端保持薄，Rust Core 保持单一产品真值，Python 仅执行 capability-gated 受限几何；
- 默认程序化视觉链不依赖第三方神经网格 Provider；
- ADR-0023 后云端 AI 只允许 DeepSeek 文本设计与千问视觉证据/比较；
- 不训练基础 3D 模型，不自建常驻 GPU 集群，不把某一家模型输出变成资产版本真值；
- 每次网络推理有明确授权、预算、超时、取消、用量记录和停止条件。

第一商业切入分布是机械硬表面外观：机器人/机械臂、工业设备、未来设备与虚构道具，以及后续经过 Gate 晋级的无人机、车辆和航空器外观概念。角色、有机物、毛发、布料、扫描级人物重建、工程 B-Rep、制造和认证不进入同一 P0。

## 3. 单一产品真值与双生成来源

ForgeCAD 可以有两类生成来源，但只能有一条产品真值链：

```text
程序化来源（默认）                 可选视觉/神经来源（默认关闭或按量）
typed intent / patch              evidence / prior / candidate
          \                         /
           → Rust validate / normalize
           → versioned typed design source
           → ShapeProgram / AssemblyGraph / Material / Surface
           → GLB / PBR / readback / fixed views
           → quality gate / bounded repair
           → one transient result
           → user confirm
           → immutable AssetVersion + ActiveDesignSnapshot
```

任何外部模型只能提供意图、观察证据、纹理先验或临时候选，不能：

- 直接写 `ActiveDesignSnapshot`；
- 绕过 Schema、预算、GLB readback 或质量门；
- 创建第二套不可追溯版本头；
- 把 `inferred` 伪装成图片中可观察到的事实；
- 在用户未确认时创建永久资产版本。

程序化路径保持默认，是因为它提供稳定结构、可编辑性、低边际成本和可审计 lineage。可选神经能力只在它能显著提高轮廓、曲面、纹理或参考保真度，且仍能进入同一真值链时启用。

## 4. 外观质量合同

“高质量”不再用三角形数量、纹理分辨率、单张英雄图或模型自评分定义，而由六层可观察结果共同定义：

1. **宏观形态**：轮廓、比例、姿态、重心、主要负空间和类别可读性；
2. **中观结构**：部件层级、关节/连接、壳体过渡、面板分区、线束路径和结构节奏；
3. **微观细节**：倒角、紧固件、分缝、夹具、编号、Decal、磨损和方向性表面；
4. **材质与光照**：真实 PBR 绑定、合理 roughness/normal/occlusion、稳定色彩管理与不过度掩盖缺陷的展示；
5. **跨视图一致性**：固定八视图中没有结构突变、悬浮、严重穿插、只在单角度成立的假细节；
6. **资产可用性**：真实 GLB/readback、稳定 Part/Material Zone、可选择、可继续修改、可恢复和可导出。

自动 Gate 负责可确定化事实，独立真人负责审美和用途判断。VLM 可以提供 `observed | inferred | unknown` 证据和局部修复建议，但不能替代真人评分，也不能覆盖确定性失败。

## 5. 成本和延迟边界

默认执行顺序必须从低成本、可缓存、可确定的步骤开始：

```text
本地范围/Schema/预算检查
→ 输入 hash 与缓存命中
→ 必要时轻量视觉证据提取
→ typed source 编译与本地 hard gate
→ 只有审美或参考差异无法确定化时调用更强模型
→ 最多两次同一意图局部修复
→ 停止、展示唯一结果或明确失败
```

每个实验和产品 Turn 必须记录：调用次数、token/图片/生成用量、缓存命中、端到端耗时、失败类别、修复次数和估算可变成本。以下是商业验证目标，不是当前已实现事实：

- 首次有效结果中位数低于 5 分钟，P90 低于 10 分钟；
- 单个付费周期的可变推理与存储成本不高于实收收入的 25%；
- 默认 1K PBR；2K/4K、神经重建和高成本生产档按量或进入更高套餐；
- 平价订阅不提供无上限高成本推理；
- 支持 BYOK 或企业自有 Provider，但权限、用量和故障边界保持一致。

任何具体价格、额度或成本上限都必须在真实用量测量后冻结，不能由文档猜测。

## 6. 商业切入与价值假设

优先服务下列高频问题：

- 游戏/影视/UGC 小团队需要快速得到可交付的硬表面道具和设备概念；
- 独立创作者会写提示词、会看图片，但不会使用完整 DCC/CAD 管线；
- 工业设计早期概念需要多轮语言修改和一致的多视图，但不要求制造结论；
- 企业私有资产流程需要可审计 lineage、稳定版本、可替换 Provider 和本地项目数据。

商业价值不来自“又一个 text-to-3D 按钮”，而来自：

- 比黑盒单次生成更可编辑、可恢复和可追责；
- 比传统 DCC/CAD 更适合零基础用户完成第一版外观；
- 比纯 Three.js/脚本生成更接近标准资产交付；
- 用垂直基准、typed design source、局部修复和项目工作流积累难以复制的数据与产品闭环。

早期销售方式优先采用 5–10 家付费设计伙伴，而不是大规模投放。先证明用户愿意反复完成“创建→修改→确认→导出”，再扩大领域和算力承诺。

## 7. 90 天验证窗口

90 天是产品验证窗口，不是对尚未实现任务的完成承诺。任务仍必须按 `CODEX_TASK_INDEX.md` 一次领取一个。

| 时间窗口 | 工程与产品重点 | 必须得到的证据 |
| --- | --- | --- |
| 第 1–14 天 | 完成 C111B 黄金机械臂视觉资产和参考比较基线 | 结构/PBR/readback/exact-lineage 自动门；独立真人可评审工件 |
| 第 15–42 天 | C112–C115：从固定资产提取可组合 Operator、Workspace、Morphology、Profile/Section | 未见 Brief 的拓扑/轮廓/部件指纹差异；新增设计不再复制整机 fixture |
| 第 43–70 天 | A006/Q004/E004/PV006C/PV006：typed 工具循环、真实多模态组合、视觉收敛和冻结盲测 | 30 条未见硬表面任务、失败分类、时间/成本/修复次数和真人评分 |
| 第 71–90 天 | 5–10 家设计伙伴封闭试用 | 有效导出、四周留存、重复使用、付费意愿和支持成本 |

若依赖任务没有退出，时间窗口顺延，不能并行跳过前置任务制造“进度”。

## 8. Go / No-Go 门

以下为下一轮商业/产品验证的目标阈值，当前状态均为 `target`：

- 冻结 30 条未见机械硬表面任务，输入覆盖纯文字、单图、多视图和已有资产局部修改；
- 第一次合成的独立真人 `≥4/5` 比例至少 70%；最多两次原位修复后至少 85%；
- 已通过任务中，宏观和中观结构不能依赖一张英雄角度掩盖；
- 相同输入和版本的严重回归率低于 10%；
- 首次有效结果中位数 `<5 分钟`、P90 `<10 分钟`；
- 可变成本不高于实收收入的 25%；
- 至少 5 家付费设计伙伴；第 4 周仍每周使用核心创建/修改/导出闭环的伙伴不少于 50%。

达到工程门但达不到真人质量门：继续收窄外观语言，不扩大领域。达到质量门但成本不达标：优化缓存、模型路由和计费，不承诺无限生成。达不到重复使用和付费：停止扩张为通用平台，评估收窄为“机械硬表面可编辑生成工作台”或团队内部工具。

## 9. 被否决或延后的方案

### 9.1 训练自有基础 3D 模型

当前否决。数据、训练、GPU、评测和模型运维成本不适合小团队。未来只有在拥有独占高质量数据、稳定收入和明确模型差异时重新立项。

### 9.2 默认本地大模型/神经 3D

当前否决。安装体积、平台兼容、显存和支持成本违背轻量目标；第三方远程 Mesh API 也由 ADR-0023 禁止。U004 只建设 DeepSeek/千问驱动的本地受限表示，不能让插件成为首次导出的前置条件。

### 9.3 四个领域同时达到生产质量

延期。四领域保留为 Core 通用性和安全边界的验证资产，不再是第一商业版本同时退出的承诺。先完成机械硬表面垂直分布，再逐领域晋级。

### 9.4 用更多固定模板提升成功率

否决为主路线。固定 Recipe 可作为 reviewed substrate 和回归 fixture，但 C112–C115 必须形成可组合设计语言；新增一个 Brief 不应要求新增一整套整机坐标。

### 9.5 只交付不可编辑神经网格

延期为可选快速模式。任何进入正式项目的结果仍需至少通过 GLB/readback、版本、来源、基本可选层级和导出合同；不能绕过单一产品真值。

## 10. 影响

积极影响：

- 目标从无界“各种高质量 3D”收敛为可以冻结样本和判定成败的垂直产品；
- 现有 Rust、版本、readback、PBR、参考证据和工作台投入直接成为壁垒；
- Provider 可以替换，团队不必押注单一模型；
- 成本、质量和商业指标进入同一完成定义。

代价与限制：

- 第一阶段不会覆盖角色、有机物或扫描级重建；
- 视觉设计语言建设仍需高质量手工基线、数据和真人审阅；
- 程序化路径可能在自由曲面上落后于神经模型，需要保留可选候选接口；
- 用户会看到明确失败，而不是始终得到一个低质量默认模板。

## 11. 与现有决策的关系

- 保留 ADR-0019 的程序化视觉默认路线和受限编译边界；
- 保留 ADR-0017 的 Rust-owned DesignWorkspace 与视觉收敛方向；
- 不改变 `ActiveDesignSnapshot`、preview→confirm、单 renderer、Key/对象库和安全范围合同；
- 将“首批四领域同时作为商业 P0 退出”调整为“机械硬表面先行、领域按 Gate 晋级”；
- 不把本 ADR 写入 `USER_GUIDE.md` 作为当前能力；实现状态仍由 `DOCUMENTATION_STATUS.md`、任务索引和能力—Gate 矩阵记录。
