## 1. 当前一句话结论

ForgeCAD 是具有类别开放理解入口和统一资产源谱系的本机 Alpha：Rust-owned 状态、受限几何、GLB/PBR/readback、唯一结果、确认/版本/导出和重启恢复已有工程证据。U002 已让任意文本、sealed 图片、多视图和活动资产进入同一对象理解/视觉合同/表示计划；U003/U004 已让经过验证的机械臂、`procedural.generic_hard_surface_v1`、开发期受限 `procedural.generic_visual_exterior_v1`、受限 `deformable.local_lattice_shell_v1`，以及二者逐部件组合的本地硬表面 Hybrid UAS@2 路径进入同一 author→build→同源 PBR capture→最多一次 VP204 typed patch 工程链。通用外观代理目前可把车辆、家具、建筑、植物、动物、角色、机械设备、虚构游戏道具和未知对象编译为不同部件组合，但仍是轻量外观代理，不是照片级重建或正式跨类别质量通过。经过同源 capture/evaluate 的非游戏 UAS@2 preview 现在携带 Rust 验证的通用 provenance，可沿既有原子确认事务持久化其 source/hash；它不再伪造旧 Domain Pack、C111 或 V003 decision。Hybrid 只允许审查过的硬表面程序化部件与固定 `2×2×2` cage 外壳部件混合，不是人物、生物、任意网格、mesh seed 或神经重建能力。U004A 已删除 Fal/Hunyuan 远程生成运行时，并把 AI Provider 固定为 DeepSeek 文本设计与千问视觉理解/比较。游戏 delivery 的 source LOD0 与 delivery GLB 现已有专用双工件原子持久化、经 receipt 重验的直接导出，以及 `ForgeAssetPackage@2` 双 hash 包装基础；确定性有效 GLB 的 source→delivery→capture→preview→confirm→export/package E2E、receipt 篡改拒绝、确认幂等和 source/delivery CAS 存储漂移拒绝回归已通过，且工作台已经提供 bounded profile intent（Rust 从实际可执行部件派生 collision，Provider 不能自报绑定）。确认后的游戏资产 ChangeSet 现在也通过专用 source/delivery 双工件 preview→confirm 原子 repository/bridge 路径保持两套 GLB 身份，native compatibility 的 `:preview → :preview.glb → :confirm` 全路径回归已通过；仍缺 packaged loader、真实千问视觉质量和跨类别盲测；当前复杂有机类别仍可能返回 typed limitation。
