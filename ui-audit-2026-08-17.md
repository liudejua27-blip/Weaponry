# ForgeCAD Viewer UI Audit — 2026-08-17

## Audit scope

- Surface: current-source ForgeCAD Runtime Viewer frontend.
- Flow: modeling empty state → compare empty state → review issue → issue drawer → compact desktop layouts.
- Capture: in-app Browser at 1672×941, 1180×760 and 900×760.
- Target: efficient desktop review with clear Runtime truth, keyboard access and no fabricated model state.

## Steps and health

1. Modeling workspace — **Good foundation; needs empty-state recovery polish.**
   - Evidence: `audit-01-modeling.jpg`.
   - Strength: the canvas, side rails and command families have clear hierarchy.
   - Risk: disconnected/no-project status leaves many disabled controls visible while the primary blue Export action remains available.
2. Compare workspace — **Needs improvement.**
   - Evidence: `audit-02-compare.jpg`.
   - Risk: the empty state is mostly blank; prerequisites and the next useful action are not prominent enough.
3. Review workspace — **Understandable, but the issue classification is misleading.**
   - Evidence: `audit-03-review.jpg`.
   - Risk: a Runtime connection failure is rendered as a spatial canvas marker even though no model exists.
4. Issue drill-down — **Interaction works; recovery is incomplete.**
   - Evidence: `audit-04-issues.jpg`.
   - Strength: one action synchronizes the canvas marker, inspector Check tab and bottom issue drawer.
   - Risk: the drawer explains the failure but offers no Retry, reconnect or diagnostic action.
5. Minimum desktop width — **Stable.**
   - Evidence: `audit-05-compact.jpg`.
   - Strength: 1180×760 has no page overflow and retains the three-column workbench.
6. Narrow width — **No overflow, but navigation access is lost.**
   - Evidence: `audit-06-narrow.jpg`.
   - Risk: at 900×760 both side rails disappear without a visible way to open them as temporary drawers.

## Highest-impact recommendations

1. Add a single connection/project recovery state with `重试连接`, `查看诊断` and a short explanation. Disable Export until an exportable Runtime version exists.
2. Give Compare a prerequisite checklist: reference present, candidate present, fixed view available, then expose the first available action.
3. Treat connection/session failures as global issues, not geometry markers. Reserve canvas markers for candidate-bound spatial findings.
4. At compact widths, replace hidden side rails with explicit Structure and Inspector drawer buttons.
5. Add keyboard resizing for both panel handles (`ArrowLeft/ArrowRight`, Home/End) and expose the current width through ARIA values.
6. Reduce raw implementation language in the primary UI (`not-run`, raw candidate IDs); keep it in diagnostic details.
7. Measure disabled-state contrast and compact toolbar hit areas. Visible semantics are good, but focus visibility, VoiceOver order and zoom behavior still need real assistive-technology testing.

## Priority

- P0: none observed.
- P1: recovery actions/state consistency; compact-width access to hidden panels; Compare empty state.
- P2: keyboard-resizable panels; copy cleanup; contrast and target-size verification.
- P3: animation and micro-polish after the workflow issues above.

## Evidence limits

The browser audit has no authenticated Tauri Runtime bytes, so it validates frontend-owned layout, empty/error states and interactions only. It does not establish GLB quality, reference likeness, packaged-app parity, formal VoiceOver compliance or `HQ_360_PASS`.
