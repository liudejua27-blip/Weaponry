WPN-THREE-EVAL-002 report

Scope
-----
The browser preview now resolves a closed WeaponryThreeJsPreviewManifest@1
from either a local query or URI-encoded JSON manifest. The accepted query
forms are `?view=FRONT`, `?views=FRONT,BACK`, `?views=ALL`, and
`?manifest=<encoded JSON>`. View IDs are normalized to the canonical fixed
order and unknown/duplicate views are rejected. No file, URL, fetch, or
caller-provided code is read by this path.

Real render path
----------------
The preview builds the canonical KnifeSceneProgram, creates the actual
Three.js WebGLRenderer and one fixed camera per selected view, then calls
renderer.render(scene, camera) for each selected viewport. The camera receipt
records the live Three.js UUID, type, position, matrix, matrixWorld,
matrixWorldInverse, projection matrix, viewport, and deterministic camera
fingerprint. The scene receipt fingerprint is derived after scene transforms
are resolved from the live Scene/Object3D graph, semantic metadata, geometry
attribute layout, and stable object IDs.

Capture boundary
----------------
After the synchronous render pass, `window.weaponryPreviewReceipt` is first
published as `CAPTURE_READY`. With the default `capture=settled` mode it is
updated exactly once on the next animation frame to `SETTLED`. The
`?capture=capture-ready` mode leaves the one-shot receipt at the ready
boundary. Both states
retain renderer_invoked=true, visual_status=NOT_REVIEWED, and
quality_status=NOT_RUN. The receipt declares bundled-static-only@1 and does
not use external network resources. The same JSON receipt is mirrored into
the stable `#weaponry-preview-receipt` output node for `--dump-dom` or other
read-only extraction.
